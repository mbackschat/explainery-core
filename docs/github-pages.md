# Publish a film on GitHub Pages

Publish a locally verified single-file export as the story repository's website. The [shared workflow](../.github/workflows/publish-film.yml) downloads `film.html` from a selected release in the calling repository, verifies the supplied SHA-256, and deploys those exact bytes as `index.html`. It requires no film build, dependencies or narration generation on GitHub.

Generated HTML must never be Git tracked, including on a deployment branch. Keep deliveries under ignored `renders/`; release attachments and Pages artifacts carry the generated bytes outside Git history. Authored composition HTML remains source code.

## Set up a story once

1. Copy the [caller template](templates/pages.yml) to `.github/workflows/pages.yml` in the story. It works with any Explainery film. For reproducible deployments, replace `@main` with the full core commit SHA you have verified.
2. Keep `renders/` in the story's `.gitignore`. Commit and push the caller workflow to the story's default branch.
3. In the story repository's **Settings → Pages → Build and deployment**, select **GitHub Actions**. The workflow needs the declared `contents: read`, `pages: write` and `id-token: write` permissions; the normal GitHub token suffices, including for private release attachments. GitHub Pages must be available on the repository's plan.
4. After the first successful deployment, set the repository's **About → Website** field to the returned Pages URL and add the README badge below. Keep a YouTube link alongside it when one exists.

Pages normally makes the film public even when its source repository is private. A private repository's release attachment remains private; it is not a public offline-download link.

## Publish a selected delivery

Run from the story root, with dependencies installed and the film validated and assembled. Replace `film-dir` with the source project directory:

```bash
pnpm exec explainery export film-dir --single-file --out renders/pages/film.html
```

For captions, append `--subtitles renders/my-film.vtt` using the matching reviewed WebVTT file. See [HTML chapters and subtitles](../README.md#html-chapters-and-subtitles).

Verify the exported film's playback, seeking, chapter navigation and any subtitles in a browser. Keep the export associated with the verified source commit and core revision in the story's delivery notes. Then create a uniquely tagged release with the file attached and explicitly run the caller workflow:

```bash
shasum -a 256 renders/pages/film.html
gh release create <delivery-tag> renders/pages/film.html --target <verified-story-commit> --title "<delivery-title>" --notes-file <delivery-notes-file>
gh workflow run pages.yml -f release=<delivery-tag> -f sha256=<printed-sha256>
gh run list --workflow pages.yml
```

The release tag and lowercase SHA-256 select the delivery; a missing attachment or hash mismatch stops publication before deployment. Run the workflow on the default branch. Pushes and release creation alone do not publish. The workflow serializes Pages runs, and later successful deliveries replace the site at the same URL. Re-run it with an earlier retained release and its checksum to restore that delivery.

Check the completed run and the hosted page: confirm the downloaded HTML's SHA-256 and exercise playback, seeking, chapters and any subtitles at the real Pages URL. Local playback is not evidence that hosting works. Keep release attachments unchanged; publish a new release for another delivery.

## README link

Use the actual Pages URL in place of `PAGES_URL`:

```html
<p>
  <a href="PAGES_URL"><img alt="Watch in browser" src="https://img.shields.io/badge/Watch%20in%20browser-8055c9?style=for-the-badge"></a>
</p>
```

## Size and hosting limits

Multi-megabyte exports are expected because they embed the film, player and audio. GitHub documents a 1 GB published-site limit and a soft bandwidth limit of 100 GB/month; check the [current Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits) before publishing substantially larger deliveries. The single-file player downloads its embedded film before initializing, so loading time can matter well before the site-size limit.

The [folder exporter](../README.md#export-the-explainer-page) is an alternative for static hosting, but copies source audio unchanged. It does not automatically yield a smaller delivery than the single-file exporter, which compresses uncompressed narration. This workflow intentionally publishes only the selected single HTML file.

GitHub documents the underlying [reusable workflow contract](https://docs.github.com/en/actions/how-tos/reuse-automations/reuse-workflows) and [Pages artifact deployment](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).
